# PRODUCT.md — О продукте

## Что такое HealthAvatar

**HealthAvatar** — мобильное приложение, которое агрегирует биометрические данные пользователя из разных источников и визуализирует его самочувствие через живого аватара-персонажа.

Аватар меняется в реальном времени: хорошо спал → персонаж бодрый. Мало двигался → персонаж вялый. Высокий стресс → персонаж устал. Никаких цифр и графиков в главном экране — только визуальная метафора, понятная без инструкции.

**Ключевое отличие от конкурентов:** мы не собираем данные — мы их интерпретируем. Пользователь уже носит трекер. Мы объединяем всё в одну точку входа и отвечаем на главный вопрос: «почему я снова устал в 14:00?»

---

## Целевая аудитория

**Основная персона:** женщины 28–42 лет, доход 100–200k ₽/мес, городская аудитория (Москва, СПб, города-миллионники).

Портрет: уже пробовали трекеры и приложения, бросили. Хотят не похудеть к лету — хотят нормально функционировать каждый день. Скачивали Habitica, MyFitnessPal, какой-нибудь трекер сна — и удалили через 2–3 недели.

**Почему они уходят из других приложений:** перегруженность данными без понятного действия. Наш ответ — убрать цифры с первого экрана, оставить смысл.

**Вторичная аудитория:** мужчины 30–45 с опытом биохакинга, уже имеющие WHOOP или Garmin — для них HealthAvatar как агрегирующий слой поверх.

## Какие агрегаторы нейросетей используем и зачем

### Claude API (Anthropic)
**Зачем:** генерация персонализированных инсайтов и рекомендаций на основе паттернов пользователя.

Логика работы: раз в день (утром) система берёт последние 7 дней метрик пользователя, текущее состояние аватара и формирует динамический промпт → Claude возвращает 2–3 рекомендации на день, написанные живым языком (не «выпейте 2 литра воды», а «сегодня после обеда попробуй 10-минутную прогулку — твой HRV вчера был ниже нормы»).

**Почему Claude, а не GPT:** лучше следует инструкциям по тону, меньше hallucinations при работе со структурированными данными, нативная поддержка через Anthropic API.

**Режим использования:** не streaming (рекомендации генерируются в фоне, не на ходу), max_tokens ~300 на инсайт, temperature 0.7 для живости текста.

### Почему не fine-tuned модель сразу
На старте нет данных для fine-tuning. Используем RAG: база знаний по health-рекомендациям (sleep hygiene, stress management, activity) + динамический контекст пользователя. Fine-tuning — в план Year 2–3 после накопления ≥10k пользователей с разрешением на обучение.

## Какие парсеры используем и зачем

### HealthKit / Apple Health (iOS)
**Что парсим:** шаги, ЧСС, HRV, сон (фазы), данные о тренировках, уровень стресса.  
**Как:** нативный фреймворк iOS HealthKit. Пользователь даёт разрешение при онбординге, данные читаем через HKSampleQuery.  
**Зачем:** охват ~60% целевой аудитории носит iPhone, большинство трекеров пишут в HealthKit автоматически.

### Garmin Connect API
**Что парсим:** Body Battery (фирменный health score Garmin), HRV, стресс-индекс, данные активности.  
**Как:** OAuth 2.0 + Garmin Connect REST API. Webhook на обновление данных.  
**Зачем:** Garmin — основной трекер у «биохакерской» аудитории.

### Strava API
**Что парсим:** активности (бег, велосипед, плавание), данные о нагрузке.  
**Как:** OAuth 2.0 + Strava v3 API.  
**Зачем:** закрываем сегмент любителей спорта, которые не используют медицинские трекеры.

### WHOOP API
**Что парсим:** Recovery score, Strain, сон.  
**Как:** WHOOP Developer API (beta access).  
**Зачем:** нишевая, но очень лояльная аудитория. WHOOP-пользователи — это наш идеальный early adopter.

### Сбер Кольцо
**Что парсим:** шаги, ЧСС, сон.  
**Как:** Sber Health API (партнёрский доступ в roadmap).  
**Зачем:** локализация под РФ — у аудитории 25–45 Сбер Кольцо растёт как категория.

### Данные смартфона (без трекера)
**Что парсим:** шаги (акселерометр), экранное время (Screen Time API / Digital Wellbeing API), геолокационная активность.  
**Зачем:** снижаем барьер входа — приложение работает даже без трекера.
